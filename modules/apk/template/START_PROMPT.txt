Analyze the authorized Android application package configured in `target/TARGET.toml`.

If usable preparation output already exists under `extracted/jadx/`, `extracted/apktool/` and `reports/tool-output/` for the current input, reuse it instead of repeating expensive decompilation. Otherwise run `tools/apk_prepare.py`.

Use preparation artifacts to determine the actual package layout. For base + split packages, treat them together as one application and include split-provided code/resources/native libraries.

Read `[orchestration]`, `[secrets]`, and `[dynamic]` from TARGET.toml. Respect `max_parallel_agents`, defaulting to 2.

Perform prioritized static analysis first. Map attack surface, unusual/high-impact behavior, concealment/analysis-resistance indicators, grouped secret/material coverage and native baseline/deeper review. Ordinary minification/obfuscation alone is not suspicious intent.

For hard-coded material, refresh `tools/apk_secret_group.py` after deterministic scanning and use only `reports/tool-output/secret-groups.json` for LLM triage. Distinguish confirmed confidential credentials from client signing material, client SDK auth material, public configuration, runtime credentials, hashes/encodings and false positives.

For native coverage, refresh `tools/apk_native_baseline.py` when needed. Use deeper native review only for app-relevant/reachable or otherwise security-interesting libraries.

Use public research local-first. Every delegated research question must include concrete non-sensitive local facts and the exact external fact still needed. Search-only leads must not change findings.

Maintain throughout:
- `findings/inventory.md`
- `findings/attack-surface.md`
- `findings/secrets.md`
- `findings/findings.md`
- `findings/dynamic.md`
- `findings/coverage.md`
- `findings/research.md`
- `findings/analysis-log.md`

After the static findings have been validated, inspect `[dynamic].enabled`:

- If false, record dynamic analysis as intentionally not run and complete the static report.
- If true, execute the workflow defined by `.opencode/commands/dynamic.md` using only the toolkit-managed Android Emulator. No external Android device is allowed or required.
- Start with `python3 tools/apk_dynamic.py probe`. KVM is accepted only when the emulator self-check confirms it. LXC without `/dev/kvm` and a VM without nested virtualization are explicit environment limitations; never alter the host from the workspace.
- Dynamic setup must use a documented compatible package/runtime ABI path and then pass the real boot smoke test. On x86_64, ARM-only package native code may use Android 11/API 30 x86_64 multi-ABI compatibility only when `minSdk <= 30` and that fallback is enabled. Label this API-30 compatibility coverage, not target-OS coverage. If no documented compatible runtime exists, report `UNAVAILABLE` rather than guessing.
- Reuse a successful `/dynamic-setup` AVD instead of recreating it for the full dynamic run.
- Dynamic evidence may confirm or narrow static hypotheses, but unobserved behavior is not proof of absence unless the relevant feature was actually exercised.
- If active validation is enabled, use `tools/apk_dynamic_action.py` exclusively so local actions are constrained and audited. Do not broad-fuzz or use ad-hoc active ADB commands.
- Active validation remains emulator-local. Do not craft/replay/mutate backend/provider API requests under the APK dynamic gate.

At completion create/maintain `reports/STATIC_SECURITY_REPORT.md`. When dynamic analysis ran, also create `reports/DYNAMIC_SECURITY_REPORT.md` and incorporate validated runtime changes into the compact `## Analyst summary` near the top of the static report.

The analyst summary must state: whether any Critical/High finding was independently confirmed, highest supported severity, top three risks at most, unusual behavior found (or none), concealment/analysis-resistance state with evidence, and the single most important remaining limitation.

Repeat the same compact analyst summary in the final OpenCode response. The human-readable reports do not replace the structured `findings/` records.
