Analyze the authorized Android application package configured in `target/TARGET.toml`.

If usable preparation output already exists under `extracted/jadx/`, `extracted/apktool/` and `reports/tool-output/` for the current input, reuse it instead of repeating expensive decompilation. Otherwise run `tools/apk_prepare.py`.

Use the preparation artifacts to determine the actual package layout. For a single-package input, analyze the prepared APK normally. When preparation produced a base package plus split packages, treat them together as one application: use the base manifest for the primary component/permission surface, inspect split-provided code/resources/native libraries, and record any additional package-data coverage or limitations. Do not assume a split/container layout when the input is a normal APK.

Read `[orchestration]` from TARGET.toml. Respect `max_parallel_agents` for concurrently executing delegated tasks, defaulting to 2 when absent.

Map the attack surface first, then perform prioritized static security analysis. Keep the primary context small.

For hard-coded secret/material coverage, refresh `tools/apk_secret_group.py` after the deterministic scan and perform AI triage from `reports/tool-output/secret-groups.json`. Do not feed the raw `secret-candidates.json` candidate array into the LLM workflow. Distinguish confirmed confidential credentials from exposed client signing material, client SDK authentication material, public client configuration, runtime credentials, hashes/encodings and false positives.

For native coverage, refresh `tools/apk_native_baseline.py` when needed. The baseline recursively covers base and split `.so` files and records ELF/hardening/JNI/import/string leads. Use `apk-native-reverser` only for app-relevant or otherwise security-interesting native paths; Ghidra is not required for every third-party library.

For public research use local-first behavior. Only externally answerable residual questions go to `apk-researcher`, and every delegated research question must include 2-5 concrete non-sensitive local facts plus the exact external fact still needed. Research workers should fetch/read a primary source immediately after discovery before broadening search. Respect `research_max_questions`, `research_max_sources_per_question`, and `research_max_report_words` from TARGET.toml, defaulting to 3, 5 and 900.

`findings/research.md` is only a compact index. Each public question gets exactly one canonical detail file under `reports/research/RQ-XX-....md`; do not create a separate batch-summary report. Perform cheap deterministic local correlation after research before marking something unresolved. Search-only source leads must not change findings without verified source support and local applicability.

Maintain the structured workspace records throughout the run:
- `findings/inventory.md`
- `findings/attack-surface.md`
- `findings/secrets.md`
- `findings/findings.md`
- `findings/coverage.md`
- `findings/research.md`
- `findings/analysis-log.md`

`findings/coverage.md` must state actual/intentional tool use, grouped secret/material coverage, native baseline vs deeper native-review coverage, split/container coverage when applicable, and degraded coverage. `findings/analysis-log.md` records concise subagent provenance, result paths and observed peak concurrency rather than repeating finding prose.

Detailed non-research work belongs in `reports/subagents/`; one canonical detail artifact per research question belongs in `reports/research/`.
At completion create `reports/STATIC_SECURITY_REPORT.md` as the consolidated human-readable report, including limitations, validation status, material research-driven changes, grouped secret/material coverage, native baseline/deeper-review coverage, split/container limitations when applicable, and a short Tools/Coverage summary. The final report must not replace the structured `findings/` records.
